# 复旦开源贡献看板：简要方案

## 现状

华科把本校开源组织的仓库标记为不同 SIG，再统计这些仓库中的 GitHub Commit、Pull Request 和 Issue。仓库归属决定 SIG 分组；公开仓库里的贡献者不一定是该校学生。参考：[华科贡献看板](https://osd.openatom.club/)与 [GitHub 仓库自定义属性](https://docs.github.com/en/organizations/managing-organization-settings/managing-custom-properties-for-repositories-in-your-organization)。

复旦已有开放原子开源社团，校方公开提到开源智算、云原生边缘计算、开源鸿蒙、开源安全、手机智能体助手、Rust 六个兴趣小组，但尚需向社团确认正式名称、负责人和项目仓库。参考：[复旦学院公告](https://cs.fudan.edu.cn/95/a3/c23787a759203/page.htm)。

现有 LeadBoard 已能统计公开 GitHub 仓库的活动和贡献者。当前网站仅展示 12 个“受关注仓库”，没有校内 SIG 身份认证，也不将全球开源项目的所有贡献称作“复旦贡献”。

## 两种统计方案

| 方案 | 需要准备 | 能回答的问题 | 边界 |
| --- | --- | --- | --- |
| A：自建 SIG 仓库 | 社团确认 SIG；每组指定负责人、项目仓库及维护规则；在复旦 GitHub 组织中为仓库设置 `leadboard_sig` 属性 | 各组维护的项目有多少公开 GitHub 活动，谁参与了这些项目 | 外校贡献者也可能计入；成员在上游项目的贡献不会自动归入本组 |
| B：成员账号加受关注仓库 | 成员自愿用 GitHub 登录并确认校内身份；维护账号与成员的绑定；维护要扫描的上游仓库清单 | 已认证成员在指定知名仓库中做了哪些贡献 | 未被扫描的上游仓库会遗漏；全球仓库的活动不能未经身份筛选就算作校内成绩 |

建议先实施 A：从社团已有的活跃项目中选 2～3 组，建立仓库归属和贡献规则。再增加 B 作为独立的“成员上游贡献”视图，不与 SIG 项目榜直接相加。每项统计保留原始 GitHub 链接，排除机器人和镜像同步；成员身份应由本人授权并可撤销。

## 需要社团提供

1. 正式 SIG／兴趣小组名单、负责人及展示名称。
2. 每组纳入统计的公开仓库链接，以及仓库管理权限或负责标注属性的人。
3. 若采用方案 B，成员 GitHub 账号授权与校内身份核验方式，以及要扫描的上游仓库清单。

在这些资料确定前，LeadBoard 继续只显示“受关注仓库”的公开活动。
